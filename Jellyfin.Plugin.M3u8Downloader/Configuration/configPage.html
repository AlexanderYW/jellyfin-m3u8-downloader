Absolute path on the server where downloads are written. Files are always saved as .mkv.
How many downloads may run at once. Each one is a separate ffmpeg process writing to the same disk, so higher is not always faster.
Applied on top of the limit above. Downloads spread across several sites are ordinary; several aimed at one site is what gets your IP blocked. At 1, the queue skips past a site that is already busy and starts the next download from a different one.
Caps how fast a stream is fetched. Uncapped, a two-hour stream arrives in a couple of minutes as one dense burst of requests — the traffic shape rate limiters are built to catch. At 10 the same stream takes about twelve minutes. Lower it to 2 or 3 for a site that has already blocked you. 0 means no limit; use that if your ffmpeg is older than 5.1 and reports Option not found.
How long to wait before starting another download from the same site, so a queue of episodes does not arrive as one unbroken stream of requests. Downloads from other sites start immediately.
When a site answers with 429 or 403, every queued download from that site waits this long. A download cannot resume part-way, so retrying sooner re-requests the whole stream while the site is still refusing you — which is how a temporary throttle becomes a lasting block.
Stops a download once it has recorded this much. Applies only to streams whose length cannot be determined — live streams, which never end on their own. 0 means no limit.
Off by default, so a film whose length ffmpeg could measure is never cut short. Turn it on to cap every download, however long the source is.
Finished, failed and cancelled entries older than this are dropped from the list automatically. 0 keeps them until you clear them yourself. Downloaded files are never deleted.
How many times to retry a failed download before giving up.
Stop a download that has made no progress at all for this long, and retry it. A silent host is otherwise reconnected to indefinitely, holding its queue slot. 0 disables the check.

Routes downloads through a proxy, e.g. http://10.0.0.5:8080 or http://user:pass@10.0.0.5:8080. Applies only to this plugin's downloads, not to the rest of Jellyfin. Must use http:// even for https streams — ffmpeg does not support SOCKS proxies. Leave blank to connect directly.

Inserted before the output path. Quote values containing spaces.
Leave on unless you would rather a damaged download failed. Some hosts serve short segments (Stream ends prematurely), and the partial frame at the end of one otherwise aborts the whole download with Error muxing a packet. Skipping them costs a brief glitch at each truncated segment.
Leave on. Without it every segment opens a new connection — around 1200 of them for a two-hour stream — and connection rate is one of the first things a site's rate limiter counts. Turn it off only for a CDN that rotates the hostname per segment, which causes Cannot reuse HTTP connection for different host and truncated downloads.
